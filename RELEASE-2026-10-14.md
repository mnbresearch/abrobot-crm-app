# AbroBot CRM — release of 14 October 2026: full-app audit and fixes

Five independent audit agents went through every screen, every edge function
and migration, the public site and its claims, security and tenancy, and the
billing and messaging paths. Six engineers then fixed the findings in parallel
on disjoint files, and a seventh reviewed how their pieces fit together (three
mismatches found and fixed). Nothing in app.abrobot.ai or any other product was
touched.

## 1. What was wrong and is now fixed

### Critical
- **The whole repository was publicly downloadable from crm.mnbresearch.com** —
  docs with incident write-ups, every migration, every edge function's source,
  scripts. Cloudflare Pages served the repo root. Now only `site/` is published:
  an allowlist rebuilt by `scripts/build-site.sh` on every deploy, pointed to by
  `wrangler.toml`. `tests/publish-allowlist.test.cjs` and CI fail if a doc, SQL
  file, script, source file or source map ever lands in it.
- **The retired legacy app was still live** at /get, /onboarding, /myday,
  /priority, /compose, /analytics, /leaderboard, /super — old prices (₹1,499,
  trials, white-label), password sign-up, a broken `consume_credit` call, a wrong
  WhatsApp number, and a stored-XSS sink. Those routes are gone from
  `_redirects`; the files are kept in git but not published. Every "Sign up
  free" / "Get started" link now goes to /login; /get 301s there.
- **Counsellors could rewrite the AI agent / alert / email settings** directly
  through the database API (the "admins only" gate was UI-only) — including
  redirecting new-lead alerts to their own Telegram. Writes to `agent_config`
  are now admin-only at the database (restrictive policies).
- **Stored XSS via the chat widget's page URL.** Only http(s) URLs are stored
  (function + database CHECK + trigger); widget links and colours are validated
  on both server and widget.

### Money
- A payment whose webhook was lost was never granted. The hourly job now asks
  Cashfree about unpaid orders and grants any that were actually paid (with
  amount reconciliation), and alerts the operator.
- Refunds/chargebacks subtracted the wrong plan's time (cross-plan exploit and
  over-revocation). Revocation now subtracts exactly what that payment granted,
  converted at list price. Dispute webhooks are read from the right field; lost
  outcomes `MERCHANT_ACCEPTED` / `INSUFFICIENT_EVIDENCE` now revoke. Partial
  refunds alert the operator for a manual decision.
- Checkout failed for workspaces with long names (Cashfree's 45-character
  order-id limit). Fixed.
- Billing alerts went to the customer's own Telegram as a "new lead". They now
  go to the operator (`_shared/operator.ts`).
- Customers could not renew before lapsing (button disabled); "renews today"
  implied auto-renew. Now "Extend" and "ends today"; downgrades confirm first.
- Automations kept running after a plan expired. Only the plan's allowed number
  of rules (oldest first) runs, and the Automations screen says which are held.
- Refused attempts were counted as usage (meters like 1437/1000).
  `consume_usage` now only counts what it allows; post-send metering uses the new
  `record_usage` so nothing already sent goes unrecorded.
- WhatsApp sends now reserve the allowance before sending and give it back if
  the send fails.

### Email & messaging
- Unsubscribe links in campaigns and the signup email opened raw HTML (Supabase
  serves function pages as text/plain). All bodies now link to
  /unsubscribe on the CRM site; one-click headers still go to the function.
- **No bounce handling existed.** New `resend-events` function (Svix-verified)
  suppresses hard bounces and complaints everywhere; every sender now skips
  suppressed addresses.
- Nurture only ever processed the first 25 organisations. It now pages through
  every opted-in organisation, resuming where it stopped.
- WhatsApp: Meta's verification handshake is answered, status callbacks are
  acknowledged, the auto-reply text is configurable (it was study-abroad copy for
  every industry), and the Integrations screen can switch it on.
- Saving WhatsApp/Telegram no longer wipes a saved Phone Number ID / Chat ID or
  forces alerts on. The test-email action is rate-limited and, on the shared key,
  can only send to the admin's own address.
- system-health no longer calls Groq once per organisation per hour or alerts
  tenants every hour while a fault persists.
- The chat rate limit is keyed on the real client IP plus an org-wide cap.

### Screens
Core lead fields (name, email, phone, owner, follow-up, lost reason) are now
editable; Pipeline moves report refusals; the in-app email button shows only to
admins; WhatsApp is gated by plan; template tokens are filled the same way the
server does; "AI summary" works (CORS) and reports real failures; CSV export is
safe from formula injection; invite failures are shown; new automation rules
start paused; the AI-agent settings that existed only in the database (guardrails,
tone, teaser, header, languages, capture fields, length, creativity) are now on
the AI Agent tab; Import follows the workspace's industry and skips rows with no
contact; Archived no longer mixes tenants for the platform admin; stale copy
fixed throughout.

### Site & docs
Product/pricing copy now matches the code (API on Business, webhook events,
which sources alert, workload-based assignment, self-serve yearly billing,
acknowledgement auto-reply); Google Fonts listed as a sub-processor; favicon;
company name in the landing footer; real personal data removed from docs and code
comments; superseded docs marked; dangerous scripts made safe
(`set-own-orgs-enterprise.sql` no longer upgrades every org, `set-cron-secret.sql`
never rotates silently, isolation test uses a temp table).

## 2. Owner decisions (not changed)
1. **GST.** Pricing and terms say prices exclude GST; checkout charges the flat
   price. Either add GST at checkout or change the copy to "incl. GST".
2. **Make the GitHub repository private.** It is public, so the docs and code
   removed from the website are still readable on GitHub, and the nightly
   encrypted database backup is a downloadable artifact of a public repo.
3. **Automations when the plan can't be read**: currently nothing runs (an
   unverifiable org never gets free automations). Say if you prefer the opposite.

## 3. Deploy — in this order
1. Supabase SQL editor: run `supabase/migrations/20261014090000_audit_fixes.sql`.
   Every row of the final table must say PASS. (Functions deployed before this
   lose the auto-reply text save and post-send metering until it runs.)
2. Run `scripts/check-live-config.sql` — read-only; review any CHECK rows
   (duplicate nurture cron, operator Telegram target, policies, mnb-research).
3. Secrets (Supabase → Edge Functions → Secrets):
   - `CASHFREE_ENV` must be `production` (now required; unset = no payment
     lookups and no reminders, by design).
   - `OPERATOR_TELEGRAM_CHAT_ID` = your own Telegram chat id, for payment and
     incident alerts (or set `app_settings` `ops_telegram_*`).
   - `RESEND_WEBHOOK_SECRET` — after step 6.
4. Terminal:
   ```
   git pull --rebase
   bash scripts/deploy-all.sh "14 Oct: full audit fixes, publish only site/"
   ```
5. Check https://crm.mnbresearch.com/FEATURES.md — it must NOT show the doc. If
   it still does, Cloudflare ignored `wrangler.toml`: Workers & Pages →
   abrobot-crm-app → Settings → Builds & deployments → Build output directory:
   `site`, then retry the deployment.
6. Resend dashboard → Webhooks → add
   `https://pomsltnrxvbcafwtbtlc.supabase.co/functions/v1/resend-events`, events
   `email.bounced` + `email.complained`; copy the signing secret into
   `RESEND_WEBHOOK_SECRET`.

## 4. Verification run before release
`tsc` clean; 130/130 Node tests; 19/19 Deno tests; `deno check` clean on all
16 functions; every migration and PL/pgSQL body parses; production `vite build`
succeeds; `site/` build + allowlist test pass. Not runnable here: the migration's
VERIFY against the live database, and live checks after deploy.

## 5. Rollback
- Frontend: Cloudflare Pages → Deployments → previous → Rollback (note: that
  republishes the repo root until wrangler.toml is back).
- Functions: `git checkout 079e810 -- supabase/functions && bash scripts/deploy-all.sh "rollback"`.
- Database: the migration is additive (no data or columns removed). To restore
  an old function body, copy that one `create or replace function` statement
  from 20260917090000, 20260908090000, 20260903150000 or 20260901090000 and run
  it alone — do not re-run those whole files.
