# AbroBot CRM — release of 13 October 2026

Scope: the MNB Research multi-product engineering prompt, applied to **AbroBot
CRM only** (crm.mnbresearch.com). Nothing in app.abrobot.ai or any other product
was touched.

Repository: `~/Projects/mnb-recovery/repos/abrobot-crm-app` (GitHub
`mnbresearch/abrobot-crm-app`, public). Architecture: React 18 + Vite SPA on
Cloudflare Pages; Supabase Postgres with row-level security as the tenant
boundary; 16 Deno edge functions; pg_cron for scheduled work; Cashfree for
payments; Resend for email; Groq for the AI agent.

## 3. Deploy

1. Supabase SQL editor → paste **`scripts/apply-2026-10-13.sql`** → Run. Every
   row of the result must say PASS.
2. Then paste and run `scripts/test-api-keys.sql`, then
   `scripts/test-analytics-recovery.sql`. Every row PASS. Both undo themselves.
3. Optional secret: `RECOVERY_FROM` (falls back to `NURTURE_FROM`).
4. Terminal:
   ```
   git pull --rebase
   bash scripts/deploy-all.sh "13 Oct: API keys lifecycle, OpenAPI, limits, analytics, checkout reminders"
   ```
5. Platform screen → Abandoned-checkout reminders → set a test recipient →
   "Send test" → "Dry run now". Turn on Enabled, and only later untick Dry run.

Order matters only in one place: deploy the frontend after step 1, or the new
cards say "not set up yet" until you do (they do not break).

## 5. Rollback

- Frontend: Cloudflare Pages → Deployments → previous → Rollback.
- Functions: `git checkout b9edbd5 -- supabase/functions && bash scripts/deploy-all.sh "rollback"`.
- Database: `scripts/rollback-2026-10-13.sql` removes the new triggers and jobs
  and turns reminders off. It deletes no data; re-applying restores everything.

## 6. Limits and what needs you

- **Abandoned-checkout reminders need** Cashfree credentials (already set) so the
  pre-send check can run — without them nothing is ever sent, by design.
- **Bounces/complaints** are not yet fed back from Resend into
  `platform_email_suppressions` (needs a Resend webhook + signing secret).
- **Analytics** count browser steps only from deployment day onward, and not for
  visitors with Do Not Track/GPC on — the dashboard says so.
- **API pagination** is still offset-based.
- **New API keys default to a 1-year expiry** in the UI (choose "Never expires"
  to keep the old behaviour). Existing keys are unchanged.
- Nothing here is a security certification. The automated checks and the review
  reduce risk; they do not prove absence of defects.
